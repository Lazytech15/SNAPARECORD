// How it fits together

One shutter, four moving parts

SNAPARECORD never talks to your database directly and doesn't replace row-level security — it's the layer between "data already authorized by your backend" and "data safely sitting in the user's browser."

→

Your backend

PHP/REST, Supabase, or Firebase — RLS / security rules enforced here, not in the browser.

⇄

authApi

Direct, uncached, per-call requests with the bearer token attached automatically.

⧉

AuthDataClient

Batches GETs at login, encrypts before caching, polls on an interval, resets daily.

▣

Your UI

Reads from the verified cache instantly, updates live as polling/refresh land.

// Feature roll

Every stop, dialed in

Labeled like the aperture ring on the lens this whole thing is named after — each stop trades off differently, same as f-stops trade light for depth of field.

f/1.4

Encrypted cache, always on

Batched data is AES-256-GCM encrypted before it ever touches localStorage — unreadable and tamper-proof, no opt-out.

f/2

Background polling

Keeps cached data fresh on an interval without ever stacking overlapping requests.

f/2.8

One fetch, not fifty

A whole page's worth of endpoints load as a single batched request at login, cached until it expires.

f/4

Friendly errors, automatically

400/401/403/404/500-class errors become clear toasts instead of raw status codes or stack traces.

f/5.6

Plugs into any auth provider

Supabase, Firebase, Auth0, Google OAuth, or your own backend — it only needs a bearer-token getter.

f/8

Framework agnostic

Plain JS, React, Vue, Svelte — ships a React scaffold via npx snaparecord init but isn't tied to it.

// Backend adapters

Same shutter, three film stocks

AuthDataClient only ever calls client.request({ url, method, params, data }). Swap what sits underneath and nothing downstream — caching, polling, encryption, your React context — has to change.

npx snaparecord init axios under the hood no extra install 
// requests are plain URL + method
export const authGetClient = createGetAuthDataClient({
  client: authApi,
  requests: [
    { key: "profile", url: "/me" },
    { key: "permissions", url: "/permissions" },
  ],
  jwtSecret: import.meta.env.VITE_AUTH_CACHE_SECRET,
});
npx snaparecord init --backend supabase auto-installs @supabase/supabase-js 
// url = table, params.eq = filters
{ key: "profile", url: "profiles",
  params: { eq: { id: userId }, single: true } }

authApi.put("posts", { title }, {
  params: { eq: { id: postId } }
});

// Error handling

Status codes, translated

A 401, 403, 404, or 500 becomes plain language automatically — identical failures within a short window collapse into one toast with a counter instead of flooding the screen.
